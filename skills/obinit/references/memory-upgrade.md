# Memory 升级

本文件记录 `.agents/` 模板的代际变更，以及存量项目如何收敛到当前代际。

## 代际与插件版本

| memory 代际 | 对应插件版本 | 变更要点 |
| --- | --- | --- |
| v1 | ≤ 0.1.27 | 初始模板：单一 `active.md` 快照，无 `handoffs/` |
| v2 | 0.1.28 | `handoffs/` 交接机制、`active.md` 派生视图、progress `来源` 归因、`## 协作策略` 占位节 |
| v3 | 0.1.29 | `docs/README.md` 文档地图、`## 文档地图` 占位节与同批更新规则；0.1.30 起同代际追加体积预算与读取分级 |

memory 代际与插件版本是两个轴：插件版本记录 skill 的发布历史，memory 代际记录 `.agents/` 内容的格式与语义。头部没有代际标记的项目按 v1 处理。

## 差异检测

重复运行 `$obinit` 时，逐节对比当前模板与项目内现有文件，报告三类差异：

1. **模板有、文件没有的章节**，例如 `## 协作策略`。
2. **规则已变更的条目**，例如「任务开始更新 `.agents/active.md`」应改为「任务开始创建 handoff」。
3. **已过期的表述**，即引用已废弃路径或已改名机制的句子。

检测粒度为**章节级 + 本文件列出的变更条目**；纯措辞差异只作为「仅供参考」列出，不进入待执行项。

执行主体：agent 只报告差异，等用户确认后按最小改动执行；不自动改写、不重复追加、不重置状态。迁移前旧项目由 `$obclose` 的降级路径保持可用，迁移失败不破坏运行。

验证方式：迁移后重新逐节对比，差异为空即视为已迁移。

## v1 → v2 迁移清单

对应插件版本：0.1.28。

必做：

1. `.agents/instructions.md`：新增空的「协作策略」小节，内容由项目自填（并行策略、认领位置、worktree 使用）。
2. `.agents/instructions.md` 的「记忆库」：把「任务开始、阶段完成、会话收尾时更新 `active.md`」拆为「任务开始时创建 `.agents/handoffs/` 交接文件」和「阶段完成、会话收尾时更新 `active.md`」。
3. 创建 `.agents/handoffs/`；它默认被 git 跟踪、应提交，不需要改 `.gitignore`。
4. `.agents/active.md`：顶部加「本文件是派生视图」声明。

可选（不批量迁移）：

5. 历史 `progress.md` 条目不回填 `来源` 字段，新条目才写。
6. 既有 `lessons.md` 条目的 `下次检查` 字段保持原样，只在被验证时顺手升级为 `验证方式` / `最后验证`。

不做：

7. 不新建 spec/plan 目录，不改写既有设计/计划文档结构。
8. 不因为模板措辞变化而重写用户已有段落。

## v2 → v3 迁移清单

对应插件版本：0.1.29。

必做：

1. `.agents/instructions.md`：新增「文档地图」小节，声明 `docs/README.md` 是项目文档的事实源地图，以及改行为前先读地图、改动与文档同批提交、写实施计划时写出受影响节标题的规则。
2. 创建 `docs/README.md`：登记项目**当前状态**文档（描述系统现在如何工作）的事实范围与同步触发；`docs/adr/` 作为决策记录整体列一行。事实范围与同步触发按项目实际情况填写。
3. 时点快照不入表：设计稿、实施计划（无论由哪个工具生成，`docs/superpowers/`、`specs/`、`plans/` 等）记录当时的判断，不随后续改动更新，不逐条登记；仍按既有铁律把当前设计/计划链接进 `.agents/active.md`。
4. 项目暂无当前状态文档时：保留文档地图的表格空行并标注待补，不要删掉表格，也不要为了填满而登记时点快照。

可选（不批量迁移）：

5. 首次建立地图时只填能确定的行；定位粒度到「文件名 + 节标题」，能写行号就写行号，暂时定位不到的条目按「先定位再改行为」处理，不阻塞后续工作。
6. `.agents/progress.md` 存在排序不同的区块时（常见形态：开头一段倒序写入的积压条目，其后才是正常追加的升序区块），不必立即整理。需要归档时把连续区块**整体移出**，并让归档文件内部**按时间升序排列**——归档不是照抄，不要把一个倒序区块原样复制进新文件。

不做：

7. 不批量补写历史文档，不改写既有文档结构，不移动既有文档路径。
8. 不因为新增文档地图而在既有提交历史里追溯补文档。

## 部分接受与拒绝

如果用户拒绝某条迁移并有意保留旧写法，在该条目或 `.agents/instructions.md` 的相关位置注明「有意保留」，避免重复报告。v3 起，持久化的「已看过、有意保留」记录可写在文档地图的维护规则里。
